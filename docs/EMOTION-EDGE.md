# 情绪能力对比与优势

> 只谈跟情绪有关的东西：一致性、积累、话术、自主性/主动性、消耗、延迟、回滚、可观测。  
> 对比对象是"常见实现方式"，不点名任何具体项目。  
> 数字来源：本机实测 + DeepSeek 官方单价估算；不是第三方 benchmark。

---

## 一、先给结论

| 问题 | 常见实现 | 我们的做法 | 结果 |
|---|---|---|---|
| 一轮几个心情？ | 多模块各自算 | 单写者 + 唯一快照 | **1 个** |
| 情绪能积累吗？ | 每条消息重新演 | 60s 拍 + needs 慢变量 + 版本 | **能** |
| 话术细腻吗？ | 一套模板/一个标签 | 底色/温度/表达/场景/关系五层 | **分层** |
| 主动吗？ | 定时器/随机 | 情绪积分 + 闸门 + 配额 | **可控主动** |
| 贵吗？ | 全量上下文每轮重发 | 快照按需注入 + 缓存前缀 | **更低** |
| 慢吗？ | 云端情绪 API | 本地 CPU 90ms | **更快** |
| 能回滚吗？ | 改代码/重启 | JSON 开关 5s 热读 | **能** |
| 能验吗？ | 感觉像 | 快照/日志/闸门/requests | **能** |

## 三、消耗对比：token 与钱

### 3.1 我们的实测

| 项 | 数值 |
|---|---|
| 网关固定开销 | **219 tokens/请求** |
| 5,640 汉字 | **3,568 tokens**（0.63 token/汉字） |
| 7,524 字注入 | **约 4,700 tokens** |
| 单条回复（4,700 输入 + 300 输出） | 峰时 **≈¥0.0127**，谷时 **≈¥0.0064** |
| 1,000 条 | 峰时 **≈¥12.7**，谷时 **≈¥6.4** |
| 缓存全命中 | **≈¥0.0028/条** |

### 3.2 和其他实现比，差在哪

| 实现方式 | 额外情绪成本 | 说明 |
|---|---|---|
| 多模块全量注入 | 每轮多 2,000–5,000 tokens | 1,000 条约 +¥4–11（峰时） |
| 云端情绪分类 API | 按调用计费 + 网络 | 本地 laya = **0 API 费** |
| 单模型直演 | 无额外调用，但不可审计/回滚 | 便宜但不稳 |
| 我们（快照按需） | 219 固定 + 必要字段 | 可压到 2,000–4,700 tokens |

**计算口径**（DeepSeek `deepseek-flash`，峰时未命中缓存）：

- 多 2,000 输入 tokens：2,000 × 0.30 / 1e6 = $0.0006 ≈ **¥0.0043/条**，1,000 条 **≈¥4.3**
- 多 5,000 输入 tokens：≈ **¥0.0108/条**，1,000 条 **≈¥10.8**
- 输出 300 tokens：300 × 1.20 / 1e6 = $0.00036 ≈ **¥0.0026/条**

### 3.3 省钱的四个结构点

1. **快照是文件**：读它不花 token，只有注入字段花。
2. **本地分类**：laya CPU 推理，零 API 费用。
3. **按需注入**：不是整份状态全塞，字段可裁。
4. **缓存前缀**：人格/规则稳定放前面，命中后输入单价降到 1/50。

### 3.4 资源消耗

| 资源 | 占用 |
|---|---|
| laya 分类 | CPU，p50 90ms，单条内存小 |
| 情绪快照 | 681–692 B |
| 网关 | 单进程，1.0–1.2s/短请求 |
| GPU | 情绪内核**不需要** GPU |

## 四、延迟对比

| 阶段 | 我们实测 | 其他实现常见情况 |
|---|---|---|
| 情绪分类 | **90ms**（本地 CPU） | 云端 API：网络 RTT + 推理，通常更慢且不可控 |
| 网关注入 | 1.0–1.2s（含模型短请求） | 多模块拼接：注入越多越慢 |
| 真实一轮 | **12–28s** | 取决于模型/上下文/分段，不是情绪层单独造成 |
| 快照写入 | 60s 后台，不阻塞回复 | 每条消息重算：增加延迟 |

**结论**：情绪层本身很轻（90ms + 219 tokens 固定开销）；12–28s 主要是模型生成和分段，不是情绪计算。

## 五、话术表现：细腻从哪来

### 5.1 五层结构

| 层 | 作用 | 例子 |
|---|---|---|
| 底色 | 主情绪 | 黏人 / 平静 / 兴奋 |
| 温度 | 强度/唤醒 | 语气软硬、句子长短 |
| 表达 | 眼睛/尾巴/语气词/颜文字 | “嗯”“欸”、尾巴动作 |
| 场景 | 聊天/安慰/撒娇 | 安慰时更短、更轻 |
| 关系 | 记忆/称呼/最近的事 | 提昨天的事、叫他 |

五层读同一份快照，所以不会“嘴上黏人、表情平静”。

### 5.2 实测指标

| 指标 | 当前 | 判断 |
|---|---|---|
| 长度中位数 | 12.5 字 | 接近短句聊天 |
| ≤15 字占比 | 90.9% | 不写小作文 |
| 语气词行占比 | 45.5% | 偏高，仍在调 |
| 句号收尾率 | 100% | **问题**，短句不该都有句号 |
| 固定填充词“嗯” | 40.9% | **问题**，换词没换习惯 |
| 分析腔词 | 0 | 没有“这组对照说明问题” |
| 相邻 7 字复读 | 0 | 指标失效，改用填充词密度 |

### 5.3 为什么比“模板话术”强

- 模板：同一句“我在”反复用，换场景不换话。
- 我们：同一底色下，温度/场景/关系不同，句子长短、语气、动作都变。
- 模板：没有情绪事实，只有字符串。
- 我们：先有快照，再决定怎么说；说错了能查是哪一层。

### 5.4 诚实的短板

- 句号率和“嗯”密度仍未达标。
- 长上下文时，细腻会被记忆/状态块挤掉（有 6,000 字预算）。
- 细腻不是每句都漂亮；允许碎、允许停一半。

## 六、自主性/主动性：不是定时器，是情绪积分

### 6.1 机制

```
情绪快照（valence/arousal/needs）
        ↓
欲望积分（want）→ 阈值（threshold）
        ↓
开口闸门（allow/deny + code + explain）
        ↓
配额（每天/每小时/分源）+ 静默/峰时
        ↓
真正开口 / 继续憋着
```

### 6.2 快照里直接驱动行为

| 字段 | 影响 |
|---|---|
| `proactive_mult` | 主动倾向倍数（示例 1.031） |
| `topic_initiative` | 开新话题倾向（0.548） |
| `avoidance` | 回避倾向（0.027） |
| `reply_len_mult` | 回复长度（1.016） |
| `first_delay_mult` | 首条延迟（0.969） |
| `meme_density` | 表情密度（0.319） |

这不是“随机发消息”，而是**状态 → 积分 → 闸门 → 配额**。

### 6.3 对比

| 维度 | 定时器/随机 | 纯 prompt 主动 | 我们 |
|---|---|---|---|
| 什么时候开口 | 固定时间 | 模型自己决定 | 情绪积分 + 阈值 |
| 会不会刷屏 | 容易 | 容易 | 配额 + 静默 + 峰时 |
| 能不能解释 | 不能 | 不能 | code/explain/want |
| 能不能回滚 | 改代码 | 改 prompt | JSON 开关 |
| 情绪低时 | 照发 | 可能硬演 | 低 want → deny |

### 6.4 当前状态（诚实）

- 架构支持“情绪驱动主动”，代码里有积分/闸门/配额。
- 默认策略偏保守：多数主动源处于关闭/影子状态，避免刷屏。
- 已知问题：`will` 的跨天锁、状态快照睡眠死锁；文档里标了，不假装已解决。
- 所以：**设计强，默认克制；不是“随时乱发”**。

## 七、情绪积累：为什么不是一条消息的事

### 7.1 快照字段

| 字段 | 含义 | 示例 |
|---|---|---|
| `mood` | 主情绪 | 黏人 |
| `intensity` | 强度 | 0.511 |
| `valence` | 效价 | −0.123 |
| `arousal` | 唤醒 | 0.511 |
| `needs.bond` | 羁绊 | 96.0 |
| `needs.energy` | 精力 | 51.7 |
| `version` | 版本 | 2658 |
| `stale_after` | 过期 | 300s |

### 7.2 时间尺度

| 变量 | 尺度 | 行为 |
|---|---|---|
| valence/arousal | 秒–分钟 | 事件驱动，快 |
| needs | 分钟–小时 | 慢漂移 |
| bond/mattering | 小时–天 | 关系积累 |
| mood | 分钟 | 底色+温度合成 |
| 记忆峰值 | 天 | 显著事件沉淀 |

### 7.3 对比

| 实现 | 情绪积累 |
|---|---|
| 每条消息重新 prompt | 无，只有当前输入 |
| 单标签分类 | 只有类别，没有强度/需求 |
| 云端黑箱 | 不可见、不可回滚 |
| 我们 | 快照 + needs + version + 记忆峰值 |

**一句话**：她不是“这条消息让她黏人”，是“这段时间把她推到了黏人”。

## 八、一致性与可回滚：最被低估的优势

| 能力 | 常见实现 | 我们 |
|---|---|---|
| 一轮一个心情 | 难保证 | 单写者 + 网关同源 |
| 出问题定位 | 翻日志猜 | 快照/影子日志/闸门 JSON |
| 回滚 | 改代码/重启 | 改 `shadow_switches.json`，5s |
| 灰度 | 改配置重启 | 逐读方切 snapshot |
| 验收 | 主观 | requests==injected、mood 一致 |

## 九、我们最强的地方（一句话版）

1. **情绪一致性**：一份事实，所有读方和网关同源。
2. **情绪积累**：needs 慢变量 + version + 记忆峰值。
3. **话术分层**：底色/温度/表达/场景/关系，不是模板。
4. **主动可控**：积分 + 闸门 + 配额，不是定时器。
5. **成本可控**：本地分类零 API，快照按需注入，缓存前缀。
6. **可回滚**：JSON 开关，5 秒热读。
7. **可验证**：快照/日志/闸门/requests，全都能复现。

## 十、诚实边界

- 不是生产级：没有鉴权、没有 CI、没有完整测试。
- 没有完整上层运行时；这是情绪框架，不是整只机器人。
- 数字是本机实测/估算，换模型/机器会变。
- 价格会变，以 DeepSeek 官方账单为准。
- 句号率/“嗯”密度/主动跨天锁仍是已知问题。
