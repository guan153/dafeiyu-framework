# 设计亮点：相比其他做法强在哪

## 七个"特别好的想法"

### 1. 单写者 + 唯一事实源

情绪不是每个模块各算一份，而是只允许 `whale_affect` 写 `emotion_snapshot.json`。  
其他模块只能读或观察。这样一轮 prompt 不会同时出现"黏人/安心/平静"。

**强在**：可审计、可回滚、不会互相打脸。

### 2. 开关是数据，不是代码

`shadow_switches.json` 里每个读方一个开关，5 秒热读。  
切读方、回退、灰度都不需要改代码或重启。

**强在**：实验成本低，回滚是改一个 JSON。

### 3. 网关和模块读同一份快照

BEAM 网关（8920）在注入底色时也读 `emotion_snapshot.json`，不再自己算一个"平静"。

**强在**：解决"prompt 内部两个心情"这种最难查的冲突。

### 4. 分层情绪，而不是一个标签

底色（主情绪）+ 温度（强度）+ 表达（尾巴/语气/口癖）+ 扰动（事件）。  
读方共享底色，表达层可以不同。

**强在**：统一但不扁平，不会所有人都说同一种"开心"。

### 5. 分类器只做输入，不做事实源

laya 8 类分类器提供文本情绪特征；最终事实仍由情绪内核写。  
低置信回退词表，失败不阻塞。

**强在**：模型错的时候，系统还能降级运行。

### 6. 证据优先的验收

不是"感觉像"，而是看：

- `emotion_snapshot.json` 时间和内容
- `[emotion-shadow]` 各 reader 的 mood
- `voice_gate.json` 的 want/threshold/decision/explain
- 8920 `/health` 的 requests/injected

**强在**：每个结论都能复现。

### 7. 本地优先

分类器、网关、情绪内核都能跑在 `127.0.0.1`。  
不依赖云端黑箱，隐私和成本可控。

**强在**：可离线、可审计、可替换模型。

## 对比表

| 维度 | 常见做法 | 我们 |
|---|---|---|
| 情绪来源 | 多模块各自算 | 单写者快照 |
| prompt 一致性 | 容易多心情 | 网关+读方同源 |
| 回滚 | 改代码/重启 | 改 JSON 热读 |
| 情绪表达 | 单一标签 | 底色/温度/表达分层 |
| 分类器 | 直接当结论 | 只当输入，低置信回退 |
| 验收 | 主观感觉 | 快照/日志/闸门证据 |
| 部署 | 云端黑箱 | 本地 127.0.0.1 |
| 可替换性 | 绑死模型 | 网关/分类器可换 |

## 诚实的边界

- 这是框架切片，不是产品；上层运行时不在仓库。
- 没有 CI/完整测试，改动要自己跑验收。
- 8920 是单点，仓库没有内置守护。
- 部分读方还没完全切到快照。
- 分类器 8 类固定，反讽/长上下文弱。
- License 未定，不能直接商用/再分发。

**一句话**：我们强在"把情绪当工程事实来管"，不是强在"模型更大"。
